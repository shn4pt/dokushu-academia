Codex(GPT6.1-sol)が作った Issue #1(学び直す社会人向けの改善)に対応し、PM-1 だけを「5分の要点・架空の具体例・詳しい説明・演習」の構成に直した。PR #2(試作、レビュー対応)と PR #3(`docs/review-request.md` のひな形)は、2026-10-13 にリベースでマージ、公開済み。Issue #1 は閉じた。記録は `docs/pilot/pm-1.md`。

**照合(2026-10-14):** 編集後の PM-1 を、Opus のエージェントが 5 つの出典の全文と照合(誤りなし、言い切り 7 点を弱めた)。PR #4 でマージし、出典の確認日を 2026-10-14 に更新。記録は `docs/verify/pm-1.md`。

**残した6項目(別 Issue はまだ起票していない):** 本文クイズの選択肢の並べ替え / 要点と全体の時間の分離表示・ページ内目次 / 講座一覧の「構成案です」と出典ラベルの整理 / 目的別の入口 / 他の PM 講座への展開 / 利用者による PM-1 の検証。

**Why:** 作者は、他教材への展開を、試作を評価してから進める方針。「5分」は式(1分200字)による目安で実測ではない。全体は29分→約40分に増えた。出典の確認日(2026-10-10)は、実際に読み直していないので据え置き。

**How to apply:**
- Codex のレビューは、ユーザーが PR のコメントに依頼文を投稿し(私が `gh pr comment` で投稿してよいと許可済み)、Codex が結果を PR のコメントに書く。「再レビューが出ました」とユーザーが伝えたら、`gh pr view N --json comments` で読む。PR の監視(`set_monitor`)は、CI 失敗なども起こされるのでユーザーが見送った。
- 自動モードの判定が、`gh pr merge` を拒否した。ユーザーが設定に `Bash(gh pr merge:*)` を足してから通った。判定を回避しない。
- 教訓(レビューの指摘): 「確認していない」を「研究がない」と書かない。出典が定めていない順序(「最初に向き合う」)を正解にしない。責任分担には、チームの型の条件(機能チームは依頼した関係者)を添える。「5分」は、含む範囲と算出方法を教材の冒頭に書く。折りたたみのテストは `toBeHidden`/`toBeVisible` で見る。
- e2e は `dist` を配信する。本文を変えたら `npm run build` してから流す。スクリーンショットは、変更前を `git worktree` で別にビルドして、同じ条件で撮る。
- マージ後は `npm run history` で `lesson-history.json` を更新して、main に push する。
