# 別の目の確認: se-2(2026-10-12)

対象: `src/content/se-2.md`(セキュリティ-2 認証と認可)。執筆とは別のエージェントが、NIST SP 800-63B-4 のウェブ版と PDF、OWASP の Authorization Cheat Sheet を curl で取得して照合した。取得できなかった資料はない。

## 結論
パスワードの規則の数と要件の強さ(SHALL・SHOULD)は正しかった。読んだ範囲の外にある内容を根拠にしていた点が 2 件(サーバー側の確認、AAL2 の要件)あり、該当の節を自分で読んで、出典の範囲に加えた。ほかに、限定の抜け 1 件、言い方の強さ・まとめすぎ 4 件を直した。

## 主な判定
| 主張 | 判定 |
|---|---|
| 認可と認証の定義、認証済みでもすべてが許されるとは限らない | 裏づく |
| 15 文字・8 文字・64 文字、組み合わせの規則の禁止、定期変更の禁止、禁止リスト、管理ソフト、試行の制限、ソルトとハッシュ | 裏づく |
| 「ヒントの保存や秘密の質問を使ってはならない」 | 一部だけ(未認証の人に見えるヒント、パスワードを選ぶときの秘密の質問に限る) |
| フィッシング耐性の定義、手入力のコードは耐性なし、暗号が必要 | 裏づく |
| AAL2 の要件 | 序論(参考の節)の要約を根拠にしていた。規範は 2.2.2 の SHALL(読んだ範囲の外だった) |
| 電話網の方式は「使える条件が限られた」制限付き | 一部だけ(制限の中身は 3.2.9) |
| アクセス制御の不備の位置づけ、水平の権限昇格 | 裏づく(「大きな」は原文では "notable") |
| 推奨 1〜4 | 裏づく |
| 推奨 5「RBAC は投稿の例のような判断が苦手」 | 一部だけ(投稿は ReBAC の例。原文は "typically be preferred") |
| 「主なもの」 | 一部だけ(前半の 5 つだけを読んでいた) |
| PM の問い 3 と判定の「サーバー側の確認」 | 読んだ範囲の外(Right Location の節) |

## 対応
- OWASP の Right Location の節を読み、推奨 6「確認は正しい場所で行う(画面側の確認に頼らず、サーバー側で)」として本文に足した。問い 3 と判定の解説を、この節にもとづく形にした。出典の記録の読んだ範囲に加えた。
- SP 800-63B-4 の 2.2.2 節と 3.2.9 節を読み、AAL2 で「フィッシングに強い選択肢を少なくとも 1 つ提供しなければならない(SHALL)」、連邦機関の職員などへの要件、電話網が現時点で唯一の制限付きの認証器であることと、その条件(リスクの評価と受け入れ、制限のない代替、通知)を書いた。出典の記録の読んだ範囲に加えた。
- ヒントと秘密の質問の行に、2 つの限定を入れた。
- 「大きな懸念」を「目立つ懸念」に、「データ」を「資源」に、「主なもの」を「前半の 5 つと確認の場所」に直した。推奨 5 を「一般に優先する」にし、投稿の例を ReBAC の例として書き直した。読んでいない推奨の節を、限界の節に書いた。
- 貼り付けの判定の解説に、推奨(SHOULD)であることを添えた。
- 指摘と追加の節は、自分で原文(ウェブ版の HTML)を読んで確かめた。
