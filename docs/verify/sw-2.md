# 別の目の確認: sw-2(2026-10-12)

対象: `src/content/sw-2.md`(SWE-2 バージョン管理とレビュー)。執筆とは別のエージェントが、Pro Git 1.1、Software Engineering at Google の第 9 章・第 16 章、Google Engineering Practices の The Standard of Code Review と Small CLs、Sadowski ほか(2018)の論文(著者版の PDF をテキスト化)を、curl で取得して照合した。取得できなかった資料はない。

## 結論
事実・数字・帰属の誤りはなかった。条件の抜け 3 件(バグを見つけた 2 人の質問の範囲、所要時間の意味、集中型でのバックアップ)と、言い切りの強さ 4 件を直した。

## 主な判定
| 主張 | 判定 |
|---|---|
| Pro Git の定義、ローカル・集中型・分散型 | 裏づく(「世代」という語はない。集中型で履歴を失うのはバックアップがない場合) |
| (ファイル名, 時点, ブランチ)の対応、監査、コミットとふり返り | 裏づく |
| 作業中の変更はブランチ、開発ブランチの問題、トランクベース開発、リリースブランチ、DORA の紹介 | 裏づく |
| 第 9 章の 6 つの利点、正しさは主な利点でない、コードは負債、約 200 行 | 裏づく |
| 「変更を小さくすることが最も大事な習慣」 | 一部だけ(原文は "Probably the most important") |
| 指針の最上位の原則「承認する」 | 一部だけ(原文は "should favor approving"。機能を望まないなら拒否できる) |
| Small CLs の利点と目安(100 行・1000 行・50 ファイル)、例外、リファクタリングを分ける | 裏づく |
| 論文の方法(12 人・44 人・約 900 万件・期間)、4 つの主題、24 行・35%・中央値 1 人 | 裏づく |
| 「全体のレビューにかかる時間の中央値は 4 時間未満」 | 一部だけ(原文は待ち時間 latency。作業時間は週平均 3.2 時間) |
| 「バグを見つけたと答えたのは 2 人」 | 一部だけ(直近の自分の変更 1 件についての質問) |
| うまくいかないこと、限界(自己選択、一般化) | 裏づく |
| 判定問題・分類・クイズの答え | 裏づく |

## 対応
- 3 つの「世代」を「出てきた順に 3 つの種類」に、集中型を「バックアップがないまま壊れると履歴を失う」に直した。目次の要約も直した。
- 所要時間を「依頼してから終わるまでの所要時間(待ち時間)の中央値は 4 時間未満」とし、作業時間(週平均 3.2 時間、中央値 2.6 時間)を分けて書いた。
- バグの 2 人に「それぞれの直近の自分の変更 1 件について」と条件を足した。
- 指針の原則を「承認する方に傾くべき」にし、機能を望まないなら承認しなくてよい限定を足した。クイズの選択肢も合わせた。
- 「おそらく最も大事な習慣」「導入した初期の社員の 1 人」「多くは取り込む前に」に直した。
- 論文が、成熟度と道具が同等ならほかでも似た経験になるだろう、とも述べている点を、限界の段落に足した。
- 指摘は、執筆時に読んだ原文(論文の 3.3・5.2・6.2 節、指針、Pro Git 1.1)で、自分でも確かめた。
