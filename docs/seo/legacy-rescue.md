# 旧サイト向けの、移行の案内と進捗の書き出し(ローカル試作。Issue #23)

`docs/seo/hosting.md` §5.2 の候補 A(現行の公開リポジトリを旧サイトとして残す)の、進捗の救済を、**ローカルで検証できる形**にした試作の記録。**候補 A の採用・本番の切り替えは、決定していない。**

**この試作でしていないこと**: 本番のビルド・`deploy.yml`・`dist`・進捗の保存方式の変更。通常の本番ルート(アプリ内)からの導線の追加。旧 URL の置き換え・停止。新サイトの公開(**新サイトは、まだ公開されていない**。案内に出る URL は、試験用の仮のもの)。全教材への展開、アカウント作成、契約、ドメイン購入、DNS、権限付与、private 化、リポジトリ移転、外部へのデータ送信、ログイン・同期・決済。実利用者のブラウザの保存データの使用。

## 2. 設計

### 状態の判定(`localStorage` の `llm-learning:progress` だけを読む)
ほかのキー、`sessionStorage`、全体の列挙は、読まない。書き込み・削除・全消去(`setItem`・`removeItem`・`clear`)もしない。送信(`fetch` など)・計測もない。

| 状態 | 判定 | 画面の動き |
|---|---|---|
| 読み取りに失敗 | `getItem` が例外(ストレージの拒否など) | **空と扱わない**。自動で移動しない。原因の確認を案内。手動リンクは示す |
| 保存なし | `getItem` が `null`(読み取りは成功) | 手動リンクを示し、**3 秒のカウントダウンの後、新サイトへ移動**(「自動の移動を止める」ボタンあり) |
| 既知の正常な形式で、記録なし | **既知の項目・型だけ**の version 1 で、完了・クイズ・問題・しおり・**最後に見たレッスン**が、すべてない | 同上 |
| 正常な進捗あり | 既知の形式で、記録が 1 つでもある(**最後に見たレッスン `lastVisited` だけの場合を含む**) | **自動で移動しない**。「進捗を書き出す」と、「元の保存データを、そのまま保存する」を示す |
| JSON 破損 | `JSON.parse` が失敗 | 自動で移動しない。元のデータを、**上書き・削除しない**。「そのまま保存する」だけを示す(新サイトの「インポート」で読めるとは約束しない) |
| 未知の version・項目・型 | JSON だが、**既知の形式でない**(version 違い、`[]`・文字列、**未知の追加項目、型の違う値**を含む) | 同上 |

- 既存のアプリの `load()` は、例外・不正な形式のとき、空の状態を返す。**この判定には、流用していない**(別の実装で、状態を区別する)。
- **既知の形式の検証は、保守的**(`isKnownProgress`)。トップレベルは `version`・`completed`・`quiz`・`questions`・`reading`・`lastVisited` だけ。`completed` は文字列の値、`quiz` は `best`・`total`(数値)、`questions` は `right`・`wrong`・`streak`(数値)・`last`(`right`/`wrong`)・`at`(文字列)、`reading` は `section`・`at`(文字列)・`index`(数値、省略可)、`lastVisited` は空でない文字列。**未知の項目・型の違いは、すべて「既知でない(unknown)」**で、転送も、書き出しもしない。アプリの既存の import は、浅い型の検査で受け入れるが、**移行のために正常と確定できることとは別**として扱う。
- **書き出しは、既知の進捗の項目だけ**で作る(未知の追加項目、たとえば偽の `apiKey` 項目は、通常の書き出しに混ざらない。そのような元データは、unknown なので、そもそも書き出しを出さない)。
- **元の保存データを、そのまま保存する**ファイル(破損・未知形式・進捗あり)は、元の文字列を保つ。**「任意の生データに、API キーが含まれない」とは約束しない**。画面に、「進捗以外の内容が含まれている可能性があります。外部に共有しないでください」と出す。
- **移動の直前の再確認**: カウントダウンの最後に、保存状態を読み直し、保存なし・空のままのときだけ移動する。待っている間に、別のタブで進捗が増えたら、移動せず、書き出しの表示に切り替える。
- **運営者の設定**: ビルド時の `AUTO_FORWARD=off` で、自動転送を一括で無効にできる(手動のリンクだけ。利用者の「止める」ボタンとは別)。新サイト側の障害時に、旧側から送り直さないための、事前に検証できる設定(`rollout.md` §8 の切り戻し)。
- 書き出しの形式は、アプリの `exportJson`(`questions`・`reading` を補い、整形する)と同じ。新サイトの既存の「インポート」に、そのまま通る。
- 旧ハッシュ URL(`#/lesson/pm-1`、`#/search?q=PM` など)は、新サイトの URL に対応付ける(パスに末尾スラッシュ、search・hash はそのまま)。`//`、バックスラッシュ、制御文字、`.`・`..` の区間(エンコード含む)は、**対応付けず、新サイトのトップを示す**(外部やベース外へは、移動しない)。手動リンクにも、同じ先を使う。
- 案内の文面: 新サイトの(仮)URL、先にバックアップを取る手順、書き出し→新側「インポート」の手順、**新サイトにすでに進捗がある場合、「インポート」は置き換える(混ぜない)ので、新側のバックアップを先に取る**こと、自己診断の回答と API の設定は、書き出しの対象外であること。**通常の「進捗を書き出す」は、既知の進捗の項目だけを対象にし、自己診断の回答や API 設定の保存先は、読まない**(進捗の項目に、利用者が何を書いたかまでは、保証しない)。**「元の保存データを、そのまま保存する」は、検証できていない文字列も含むため、API キーなどが含まれないとは保証できず、外部に共有しないよう案内する**(共通の案内にも、同じ限定を書いた。「API キーは、ファイルに含まれません」という一律の断定は、しない)。「実在の新サイトが公開済み」とは、書いていない。
- JavaScript が無効: 案内と手動リンクは、静的な HTML にある。保存データの欄は、「確認には JavaScript が必要です」と出す(「確認中」のまま止まらない)。
- 新しい同期・混ぜ合わせ(merge)の仕様は、作っていない(新サイトの既存の「インポート」の動作のまま)。

## 4. 未検証(本番の条件)

- **実在の旧オリジン(`https://shn4pt.github.io/dokushu-academia/`)**での動作。実際の GitHub Pages の配信、CSP の扱い、`main` の置き換えの手順。
- **実在の新サイト**の URL・ドメイン・配信。この試作の自動転送は、ローカル宛先だけを許可している。本番の宛先を許可する変更と、その検証は、別の作業。
- 実利用者の、実際の保存データ(旧バージョンの形式を含む)での読み書き。ブラウザごとの差(Safari の保存制限、プライベートモード、ストレージの自動削除)。
- ダウンロードの挙動(ブラウザごとの保存先、スマホでの保存)。**スマホで、書き出したファイルを新サイトに読み込ませる流れは、検証していない**(画面の見た目だけ、390px で確認)。
- 旧 URL を、検索エンジンや外部のリンクが指し続ける影響。案内ページの SEO。
- アクセシビリティの検査(スクリーンリーダーなど)。文面の、利用者による検証。
- 自動転送の 3 秒が、適切か。
