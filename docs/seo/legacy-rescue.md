# 旧サイト向けの、移行の案内と進捗の書き出し(ローカル試作。Issue #23)

`docs/seo/hosting.md` §5.2 の候補 A(現行の公開リポジトリを旧サイトとして残す)の、進捗の救済を、**ローカルで検証できる形**にした試作の記録。**候補 A の採用・本番の切り替えは、決定していない。**

**この試作でしていないこと**: 本番のビルド・`deploy.yml`・`dist`・進捗の保存方式の変更。通常の本番ルート(アプリ内)からの導線の追加。旧 URL の置き換え・停止。新サイトの公開(**新サイトは、まだ公開されていない**。案内に出る URL は、試験用の仮のもの)。全教材への展開、アカウント作成、契約、ドメイン購入、DNS、権限付与、private 化、リポジトリ移転、外部へのデータ送信、ログイン・同期・決済。実利用者のブラウザの保存データの使用。

## 2. 設計

### 状態の判定(`localStorage` の `llm-learning:progress` だけを読む)
ほかのキー、`sessionStorage`、全体の列挙は、読まない。書き込み・削除・全消去(`setItem`・`removeItem`・`clear`)もしない。送信(`fetch` など)・計測もない。

| 状態 | 判定 | 画面の動き |
|---|---|---|
| 読み取りに失敗 | `getItem` が例外(ストレージの拒否など) | **空と扱わない**。自動で移動しない。原因の確認を案内。手動リンクは示す |
| 保存なし | `getItem` が `null`(読み取りは成功) | 手動リンクを示し、**3 秒のカウントダウンの後、新サイトへ移動**(「自動の移動を止める」ボタンあり) |
| 既知の正常な形式で、学習記録なし | version 1 で、完了・クイズ・問題・しおりが、すべて空 | 同上 |
| 正常な進捗あり | version 1 で、記録がある | **自動で移動しない**。「進捗を書き出す」と、「元の保存データを、そのまま保存する」を示す |
| JSON 破損 | `JSON.parse` が失敗 | 自動で移動しない。元のデータを、**上書き・削除しない**。「そのまま保存する」だけを示す(新サイトの「インポート」で読めるとは約束しない) |
| 未知の version・形式 | JSON だが、version 1 の形でない(`[]`、文字列を含む) | 同上 |

- 既存のアプリの `load()` は、例外・不正な形式のとき、空の状態を返す。**この判定には、流用していない**(別の実装で、状態を区別する)。
- 書き出しの形式は、アプリの `exportJson`(`questions`・`reading` を補い、整形する)と同じ。新サイトの既存の「インポート」に、そのまま通る。
- 旧ハッシュ URL(`#/lesson/pm-1`、`#/search?q=PM` など)は、新サイトの URL に対応付ける(パスに末尾スラッシュ、search・hash はそのまま)。`//`、バックスラッシュ、制御文字、`.`・`..` の区間(エンコード含む)は、**対応付けず、新サイトのトップを示す**(外部やベース外へは、移動しない)。手動リンクにも、同じ先を使う。
- 案内の文面: 新サイトの(仮)URL、先にバックアップを取る手順、書き出し→新側「インポート」の手順、**新サイトにすでに進捗がある場合、「インポート」は置き換える(混ぜない)ので、新側のバックアップを先に取る**こと、自己診断の回答と API の設定は、対象外(API キーは、ファイルに含まれない)こと。「実在の新サイトが公開済み」とは、書いていない。
- JavaScript が無効: 案内と手動リンクは、静的な HTML にある。保存データの欄は、「確認には JavaScript が必要です」と出す(「確認中」のまま止まらない)。
- 新しい同期・混ぜ合わせ(merge)の仕様は、作っていない(新サイトの既存の「インポート」の動作のまま)。

## 3. 検証

**環境**: macOS、Node 22、Chromium(Playwright)。2 つのオリジン(旧 4177、新 4175)。ブラウザのデータは、テストごとの新しいコンテキストだけ。外部へのアクセスはない。

**コマンド**: `npm run build:legacy-rescue && npm run build:path:root && npm run build:path && npx playwright test --project=legacy`(2026-10-15)。

**結果: 27 件が成功。**

| 検査 | 結果 |
|---|---|
| 保存なし・学習記録なしの正常形式: 手動リンクが先に出て、カウントダウンの後に、新サイト(`http://localhost:4175/`)へ移動 | 成功 |
| 「自動の移動を止める」で、止まる。手動リンクは残る | 成功 |
| 正常な進捗あり: 3 秒を超えても移動せず、手動リンクを示す | 成功 |
| JSON 破損・未知の version・配列・文字列: 移動せず、元の文字列を**一字一句同じまま**保存でき、`localStorage` の値が変わらず、`setItem`・`removeItem`・`clear` が 0 回 | 成功(4 状態) |
| ストレージの読み取りに失敗: 空と扱わず、移動せず、白紙にならず、ページ内エラーなし | 成功 |
| JavaScript が無効: 案内と手動リンクが見え、「確認中」で止まらない | 成功 |
| 旧ハッシュ URL(`#/lesson/pm-1`、`#/course/pm`、`#/lesson/nothing`、`#/search?q=PM`、エンコードされた検索語): 新サイトの対応する URL へ(手動リンクも同じ) | 成功(5) |
| `#//example.com`、`#//example.com/`、`#/\example.com`、`#/../../x`、`#/%2e%2e/x`: 外部へ移動せず、新サイトのトップへ。`example.com` へのリクエストなし | 成功(5) |
| 往復: 旧側で書き出し → **別オリジン**の新サイトの「インポート」で、`completed`・`quiz`・`questions`・`reading`・`lastVisited` の 5 つが、そのまま保たれる。旧側の元データは変わらず、書き込み・削除なし。読んだキーは、進捗のキーだけ | 成功 |
| `questions`・`reading` のない古い形式: 書き出しで補われ、新サイトで読み込める | 成功 |

| `rescue.js` に、書き込み・削除・送信・計測・全体の列挙の語がない(静的) | 成功 |
| 通信は、旧サイトのオリジンの静的ファイルだけ(POST なし、外部ホストなし) | 成功 |

**回帰**: `npx playwright test`(desktop・mobile・path・diag・legacy)で、1042 件が成功(3 件スキップ。ハッシュ版の回帰を含む)。型チェック・`npm run build` も成功。
