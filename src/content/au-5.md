### IT への対応とは何か

基準は、**IT への対応**を、組織目標を達成するために、**あらかじめ適切な方針と手続を定め**、それを踏まえて、業務の実施において組織の内外の IT に**適時かつ適切に対応する**こと、と定めます。そして、次のように位置づけます。

- IT への対応は、ほかの基本的要素と**必ずしも独立に存在するものではない**。
- ただし、業務内容が IT に大きく依存している場合や、情報システムが IT を高度に取り入れている場合などには、内部統制の目的を達成するために**不可欠の要素**として、内部統制の有効性に係る**判断の規準**となる。
- IT への対応は、**IT 環境への対応**と、**IT の利用及び統制**からなる。

2023 年の改訂では、**IT の委託業務に係る統制**の重要性が増していること、**サイバーリスクの高まり等を踏まえた、情報システムに係るセキュリティの確保**が重要であることが記載されました。ただし、実施基準は、IT への対応を基本的要素に加えたことは、**組織に新たな IT システムの導入を要求したり、既存の IT システムの更新を強いたりするものではない**、と書いています。

([セキュリティ-1](/lesson/se-1)から見てきた情報の守り方と、ここでの IT の統制は、重なる部分があります。ただし、金融商品取引法の内部統制報告制度で求められる IT の統制は、**財務報告の信頼性**のためのもの、と実施基準は書いています(後述)。この対応づけは、このサービスの整理です。)

### IT 環境への対応

**IT 環境**とは、組織が活動するうえで必然的に関わる、内外の IT の利用状況です。実施基準は、組織が考慮する項目の例として、次の 5 つを挙げます。

1. 社会及び市場における IT の浸透度
2. 組織が行う取引等における IT の利用状況
3. 組織が選択的に依拠している一連の情報システムの状況(依拠しているかどうか、どのような情報システムか)
4. IT を利用した情報システムの安定度
5. IT に係る外部委託の状況

IT 環境への対応は、統制環境にだけ関連づけられるのではなく、個々の業務プロセスの段階で、ほかの基本的要素と**一体となって評価**される、とされています。

### IT の利用:ほかの要素を、IT で支える

実施基準は、IT を内部統制に使うと、**より有効かつ効率的な内部統制の構築ができる**とし、基本的要素ごとに、例と注意を書いています。

| 要素 | IT の利用の例(基準の要点) | 注意(基準の要点) |
|---|---|---|
| 統制環境 | 電子メールで、経営者の意向や方針を適時に伝える | 経営者や重要な構成員が、電子メールで、容易に不正を共謀することも可能になりうる。防ぐ統制活動が要る |
| リスクの評価と対応 | 売掛債権の発生と回収を適時に把握し、回収が滞るものを別に管理する。リスク情報の共有状況を把握して見直す | |
| 統制活動 | 統制活動の自動化。例:生産管理システムに棚卸の検証プログラムを組み込み、帳簿在庫と実在庫の差を瞬時に把握する。迅速で、人間の不注意による誤謬を防げる | プログラムの不正な改ざんや使用があると、**プログラムに精通した者しか対応できず、不正等の適時の発見が困難**になりうる。適切なアクセス管理が要る |
| 情報と伝達 | 承認や作業が一定期間に行われないと、上司に伝わる機能。外部へのメッセージ掲載や、外部からの情報収集 | 外部への公開や外部からの収集に使うときは、外部からの不正な侵入への防止措置が要る |
| モニタリング | 日常的モニタリングを、システムに組み込んで自動化し、より網羅的に行う。独立的評価の頻度や人員を減らせることもある | 監視する指標を、あらかじめ設定してプログラムしておく必要があり、システム設計の段階から準備が要る |

そのうえで、実施基準は、IT を高度に取り入れた情報システムの**問題**を、2 つ挙げます。

- 手作業の情報システムと違い、**稼働後の大幅な手続の修正が困難**である。
- システムの仕様によっては、IT で実施した手続や情報の**変更等が、適切に記録されない**ことがあり、**事後の検証が困難**となる。

したがって、IT を使った情報システムの特性を十分に理解し、**あらかじめ計画的に準備**し、**適切な事後の検証方法を検討しておく**必要がある、とします。(記録を残すという点は、[前のレッスン](/lesson/au-4)と重なります。)

なお、内部統制に IT を使わず、手作業で運用している場合に、手作業による誤謬等を防ぐ統制を別に作る必要が生じうるが、**そのことが直ちに内部統制の不備となるわけではない**、とも注意しています。

### IT の統制:目標と、2 つの種類

**IT の統制**は、IT を取り入れた情報システムに関する統制で、自動化された統制を中心としつつ、しばしば手作業による統制が含まれる、とされます。経営者が設定する**IT の統制目標**の例として、実施基準は、次の 4 つを挙げます。

| 目標 | 内容(基準の要点) |
|---|---|
| 準拠性 | 情報が、法令、会計基準、社内規則等に合致して処理されている |
| 信頼性 | 情報が、組織の意思・意図に沿って承認され、漏れなく正確に記録・処理される(**正当性、完全性、正確性**) |
| 可用性 | 情報が、必要なときに利用できる |
| 機密性 | 情報が、正当な権限を持つ者以外に利用されないように保護されている |

財務報告の信頼性を確保するための IT の統制は、会計上の取引記録の**正当性、完全性及び正確性**を確保するために実施されます。実施基準は、**正当性**を、取引が組織の意思・意図に沿って承認され行われること、**完全性**を、記録した取引に漏れや重複がないこと、**正確性**を、取引が財務や科目分類などの主要なデータ項目に正しく記録されること、と説明します。金融商品取引法の内部統制報告制度では、IT の統制も、財務報告の信頼性を確保するために整備するもので、**それ以外の目的のための IT の統制の整備と運用を、直接求めるものではない**、とされています。

IT に対する統制活動は、**全般統制**と**業務処理統制**の 2 つからなり、完全かつ正確な情報の処理を確保するには、両者が**一体となって機能する**ことが重要だ、とされます。

| | 全般統制 | 業務処理統制 |
|---|---|---|
| 基準の説明 | 業務処理統制が**有効に機能する環境を保証**するための統制活動。通常、複数の業務処理統制に関係する方針と手続 | 業務を管理するシステムで、承認された業務が**全て正確に処理、記録される**ことを確保するために、業務プロセスに組み込まれた IT に係る内部統制 |
| 例 | システムの開発・保守に係る管理、システムの運用・管理、内外からのアクセス管理などシステムの安全性の確保、外部委託に関する契約の管理 | 入力情報の完全性・正確性・正当性等を確保する統制、例外処理(エラー)の修正と再処理、マスタ・データの維持管理、認証・操作範囲の限定などアクセスの管理 |
| 単位 | 通常、**IT 基盤**(ハードウェア、ソフトウェア、ネットワーク等)を単位に**構築**する。評価も、IT 基盤をもとに評価単位を識別する | 評価は、基本的に**個々のシステム**ごとに行う |

実施基準は、全般統制がなぜ必要かを、こう説明します。IT を使った情報システムでは、いったん適切な業務処理統制を組み込めば、**意図的に手を加えない限り、継続して機能する**性質があります。しかし、その後のシステムの変更の段階で必要な統制が組み込まれなかったり、プログラムに不正な改ざんや不正なアクセスが行われたりして、全般統制が有効に機能しない場合には、**業務処理統制を組み込んだとしても、その有効性が保証されなくなる可能性**がある、と。対応の例として、**開発・変更の過程等の記録を適切に保存する**ことと、プログラムの不正な使用や改ざんを防ぐための**アクセス管理に関する対策**を挙げます。

また、実施基準は、業務処理統制は手作業でもできるが、システムに組み込むことで、より効率的かつ正確な処理が可能になる、とも述べます。

### IT を使った内部統制を、どう評価するか

実施基準は、経営者が評価する際の考え方を、次のように書きます。

- **全般統制と業務処理統制の、両方を評価**する。全般統制が有効に機能していると評価されても、**それだけで業務処理統制も有効に機能しているという結論には至らない**。
- 評価の範囲は、まず、財務報告に係る内部統制に関連する**システムの範囲を明確にする**ことから始める。業務プロセスとシステムの関連、システム間のデータの流れ、使用しているシステムの一覧を整理することが有用。**IT 基盤の概要**(IT に関与する組織の構成、規程と手順書、ハードウェア・基本ソフトウェア・ネットワークの構成、外部委託の状況)も把握する。
- **全般統制**は、IT 基盤の概要をもとに**評価単位を識別**して評価する。例:自社開発の販売・購買・物流システムをシステム部が管理し、会計システムは経理部が市販のパッケージを導入・管理している場合、評価単位は「システム部」と「経理部」の 2 つ。**業務処理統制**は、基本的に個々のシステムごとに評価する。
- 全般統制の評価の例の観点は、システムの開発・保守、運用・管理、アクセス管理などの安全性の確保、外部委託に関する契約の管理。業務処理統制の評価の例は、入力情報の完全性・正確性・正当性、エラーデータの修正と再処理、マスタ・データの正確性、認証・操作範囲の限定などのアクセス管理。
- **自動化された業務処理統制**は、一般的に、手作業による IT の業務処理統制よりも無効化が難しくなるが、**過信せず**、内部統制の無効化のリスクを完全に防ぐことは困難だという視点を持つ。電子記録に変更の痕跡が残りにくい場合は、無効化の発見が遅れることがある。
- 運用状況の評価の量について、IT を利用した内部統制は、一貫した処理を繰り返すため、**整備状況が有効と評価され、全般統制が有効**であれば、人手の統制より、サンプル件数を減らし、サンプルの対象期間を短くするなど、一般に**運用状況の評価の作業を減らせる**。
- **過年度の評価結果の利用**:IT を利用した内部統制の評価も、原則として毎期実施する必要がある。ただし、自動化された統制は、いったん設定されると、変更やエラーがない限り一貫して機能する性質があるので、過年度に不備なく運用されていると評価され、その後**変更されていないこと、障害・エラーなどが発生していないこと**、関連する**全般統制が有効**と判断できる場合には、結果を記録して、評価結果を継続して利用できる。複数会計期間に一度の頻度でテストする方法も含まれるが、**IT 環境の変化を踏まえて慎重に判断し、必要に応じて監査人と協議して行うべきで、特定の年数を機械的に適用すべきものではない**、と書かれています。

### 全社的な内部統制の評価項目の例(IT への対応)

実施基準の参考は、全社的な内部統制の評価項目の例として、IT への対応について、次のような問いを挙げます(例であり、必ずしもこの例によらない場合があります)。

- 経営者は、IT に関する適切な戦略、計画等を定めているか。
- IT 環境を適切に理解し、これを踏まえた方針を明確に示しているか。
- 手作業と IT を用いた統制の利用領域について、適切に判断しているか。
- IT を用いて統制活動を整備する際に、IT の利用で生じる**新たなリスク**が考慮されているか。
- IT に係る全般統制と業務処理統制についての方針と手続を適切に定めているか。
