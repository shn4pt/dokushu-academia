### 方法は、知りたい問いで選ぶ

利用者を調べる方法には、インタビュー、観察、ユーザビリティテストなどがあります。どれを使うかは、**何を知りたいか**で決まります。

Nielsen Norman Group(NN/g)の記事 "Why User Interviews Fail"(Rosala, 2019)は、インタビューを、利用者の**考え、信念、心的モデル、経験**を知る方法だと説明します。一方、記事は、次のような問いは、インタビューでは**信頼できる答えが得られない**と述べます。

- どの色が、製品の印象を最も高めるか。
- 人びとは、将来、この製品を買う(使う)か。
- どんな機能が、製品に必要か。

どれも妥当な問いですが、**人びとの行動についての問い**です。記事は、インタビューは行動についての信頼できるデータを生まず、行動を知るには、**観察**のほうがはるかによいと述べます。記事の例では、背景色の好みを聞いても、(1) 色に意見があると仮定する(聞かれたから意見を作る、**問い合わせ効果**)、(2) 答えが実生活の気持ちを表すと仮定する、(3) 色の好みが製品全体の印象を左右すると仮定する、という 3 つの仮定を置くことになる、と述べます。

NN/g の入門記事 "User Interviews 101"(Rosala と Pernice, 2023)は、インタビューとユーザビリティテストを、次のように比べます。

| | ユーザーインタビュー | ユーザビリティテスト |
|---|---|---|
| 目的 | 利用者、その経験、必要、困りごとについての**新しい知識**を得る | 設計を評価する(うまくいかない点とその理由) |
| 調査の種類 | **態度**(報告された行動、考え、感情を集める) | **行動**(利用者が設計と関わるのを直接観察する) |
| 設計 | ない(利用者は設計を見ない、試さない) | ある(利用者は設計と関わる) |

### まず、研究の問いを決める

GOV.UK のサービスマニュアルは、**研究の問い(research questions)**を、調査の計画と優先順位づけに使うよう述べます。最も良い時機は、新しい開発の段階の始め(特に発見、アルファ、ベータ)で、**チーム全員で**作ると、何が大切かについて合意しやすい、と述べます。進め方は、次のとおりです。

- 各自が 5〜10 分で、**次の段階で調査から知りたいこと**を、付箋に書く。
- 「誰が」「何を」「いつ」「どこで」「なぜ」のような**広く開いた問い**のほうが、「…するか」「…したか」「…だろうか」のような**狭い問い**より役に立つ(原文の狭い問いは、do / have / will / can で始まる問い)。
- これは、**自分たちが学ぶ必要のあること**で、利用者に尋ねる質問ではない。
- 似た問いをまとめ、各自が最優先と思う 5 つに点を付けて、優先順位を決める。

NN/g の記事も、関係者に、研究の目的を理解してもらい、**問いの優先順位づけに参加してもらう**と、結果が受け入れられやすいと述べます(記事の主張です)。

### 誰に会うか

GOV.UK のマニュアルは、参加者は、**実際の、または見込みの利用者**であるべきだと述べます。そして、障害のある人や、補助技術を使う人、デジタルに不慣れな人、利用に助けが要る人も含め、サービスを必要とする**さまざまな人**を含めるよう述べます。基準としては、人口統計、特定の利用者グループ、特定の経験、困った状況、サービスへの接し方を、状況に応じて挙げます。それとは別に、年齢、性別、民族、障害、社会経済的な地位に**幅**を持たせるよう述べます。

人数は、方法で決まりますが、**インタビューやユーザビリティテストの 1 ラウンドで、4〜8 人**が通例だと述べます。募集の方法として、募集会社、専門団体や支援団体、既存の利用者(許可を得て)、会場での募集、(社内向けのサービスなら)関係する職員を挙げます。ただし、**一般の利用者向けの部分の調査に、自社の職員は使わない**よう述べます(知識や経験から、違った使い方をするため)。

**同意。** マニュアルは、あらゆる調査で、参加者の**インフォームド・コンセント**(調査を理解し、参加に同意した記録)を得るよう述べます。参加者が知る必要があることとして、誰が調査をするか、目的、集めるデータ、当日の流れ、結果の使い道、**参加は任意で、いつでもやめられる**こと、データの保管期間、権利と苦情の窓口、見学者の有無、記録の有無と方法、を挙げます。**情報シート**を事前に渡すよう勧め、参加者が同意を撤回したら、調査を止め、集めたデータを消すよう述べます(セッションのあとの撤回でも、データは消します)。(これは、英国の法律の下での手引きです。日本の個人情報の扱いは、別に確認が要ります。)

### 質問の作り方

**インタビューは、雑談でなく、調査です。** NN/g の入門記事は、インタビューを、非公式な会話や営業でなく、**研究として**扱うよう述べます。進め方は、次のとおりです。

1. **目標を決める。** 広すぎる目標(「利用者を知る」)では、役に立つ洞察が得られない。(例:何が顧客に、製品を検討させ、試させるか。経験のうれしい点とつらい点は何か。何が利用者に製品をやめさせるか。)
2. **ガイドを作る。** 少数の、**開いた質問**を用意する。例は、「典型的な 1 日を話してください」「最後に〜したときのことを教えてください」「〜という経験をしたときのことを教えてください」。**一般的な手順より、具体的な出来事**を尋ねるほうが、記憶を呼び起こす。深掘りのための追加の質問(いつ起きたか、どれくらいかかったか、以前にもあったか、どう感じたか)も用意する。ガイドは柔軟に使い、順序を変えたり、飛ばしたりしてよい。
3. **試行する。** 友人や同僚、または 1 人の利用者で試し、誤解された質問、足すべき質問、外すべき質問、順序を確かめる。
4. **やさしく始める。** 目的と質問の種類、情報の使い方を説明する。ゆっくり話す。答えやすい質問から始める。個人的、批判的に受け取られる質問は避ける。
5. **信頼関係(ラポール)を築く。** 聞いていることを、言葉と非言語の合図(「なるほど」、うなずき、視線)で示す。遮ったり急がせたりしない。ラポールは友情とは別。
6. **追う。** 「それについて、もっと教えてください」「その例を挙げてもらえますか」「なぜそれが大切ですか」のような、**探る質問**。

**開いた質問と閉じた質問。** NN/g の記事(Rosala, 2024)は、開いた質問は**予想以上のことを見つける**のに役立ち、閉じた質問は確認や詳細に役立つが、**驚きを消す**と述べます。閉じた質問は、**誘導的**にもなりやすい、とも述べます。「did」「was」「is」で始まる質問は誘導的なことが多く、「how」「what」で始まる質問は開いていることが多い、という見分け方を挙げます。

| 誘導的な閉じた質問 | 誘導しない開いた質問 |
|---|---|
| その経験は役に立ちましたか | その経験は、どうでしたか |
| それは分かりやすかったですか | それについて、どう思いましたか |
| その作業は難しかったですか | その作業は、どうでしたか |

別の NN/g の記事(Schade, 2017)は、誘導を避けるルールを挙げます。**自分の言葉で言い換えない**(「写真が役に立ったと言いましたね」でなく、「写真について…?」)。**答えを示唆しない**。**画面の部品の名前を言わない**(利用者がその語を知らないことがある。指して「これは何ですか」と聞く)。**利用者の気持ちを決めつけない**(「苦労していたとき」でなく、「何が簡単で、何が難しかったですか」)。記事の例では、経験の浅い進行役が「このボタンは何をすると思いますか」と聞いて、利用者に、その文字が操作できるリンクだと気づかせてしまった、とあります。

### 現場で見る

インタビューは、**報告された行動**を集める方法です。NN/g の入門記事は、その限界として、**記憶の不確かさ**(出来事を完全には思い出せない)、**細部の欠落**(何が重要かを参加者は知らない)、**社会的望ましさのバイアス**(自分をよく見せる)、そして、**質問者の技量**に質が左右されることを挙げます。([心理学-2](/lesson/ps-2)の自己報告の限界と、[心理学-3](/lesson/ps-3)の記憶の再構成とも重なります。)利用者が**実際に何をするか**を知るには、観察するか、行動のデータを集める必要がある、と述べます。

NN/g の記事(Farrell と Fessenden, 2024)は、**現場調査(field study)**を、利用者の**自然な環境**で行う調査と説明します。種類として、次を挙げます。

- **直接観察**:介入せず、質問もしない、「壁のハエ」のような観察。自然な行動を見る。
- **コンテキスチュアル・インクワイアリー**:少数の利用者の、詳しい観察とインタビュー。
- **顧客先訪問**:観察とインタビューの組み合わせで、顧客が案内する。
- **エスノグラフィー**:その環境に長期間浸る。

現場調査は、設計の前(発見の段階)に行うと、利用者の理解を根本的に変えうる、と述べます。費用と手間がかかるため、遠隔の進行付き調査や、実験室を選ぶ場合の条件も述べています。

**コンテキスチュアル・インクワイアリー。** Beyer と Holtzblatt が考案した方法で、NN/g の記事(Flaherty, 2020)によると、調査やインタビューが、**利用者が今していない過程を、思い出して説明する**ことに頼る欠点を補います。**今していること**なら、利用者はその理由も話しやすい、という考えです。4 つの原則は、**文脈**(自然な環境で)、**協力**(利用者と研究者は、仕事を理解する協力者)、**解釈**(共有された解釈を、利用者のフィードバックで作る)、**焦点**(調査の目的を理解して観察する)です。セッションは、導入(打ち解ける、記録の同意)、移行(仕事を見ていること、気になることがあれば止めることを、はっきり伝える)、文脈の中のインタビュー(見て学び、止めて議論するの繰り返し)、最後のまとめ(最後の確認の質問をし、観察したことへの自分の解釈を説明して、利用者に訂正してもらう)、の流れです。リスクとして、利用者が「インタビューモード」に戻って過程を要約し始めること、現状への不満の披露の場になること、研究者自身の思い込みが入ること、解釈を確かめるうちに利用者の行動が変わること、を挙げます。記事の著者は、自分の経験として、自動車保険のデータ入力で、専門家へのインタビューで聞いた手順に、実際の作業では、聞いていなかった複数の手順があったと述べます(一人の著者の経験談です)。

記事は、コンテキスチュアル・インクワイアリーは、複雑なシステムや、専門家の視点を理解するのに向き、商品ページの改善のような**限定された設計課題には、あまり向かない**と述べます。

### 記録して、分析する

GOV.UK のマニュアルは、セッションの記録を、メモ、写真、音声・動画の録音・録画で行うよう述べます。記録の前に、必ず同意を得ます。メモは、**観察(見たこと、聞いたこと)**に徹し、解釈は書かないようにします。進行役は参加者に集中し、**観察者にもメモを取ってもらう**のがよい、と述べます。(ユーザビリティテストなどで、経験のある観察者がセッション中に付箋へ書く場合は、)付箋には、**1 枚に 1 つの観察**、参加者とセッションの番号を書きます。

分析は、**各ラウンドのあと、できるだけ早く**、観察者全員で行います。目安は、**調査 2 時間に対して分析 1 時間**です。手順は、次のとおりです。

1. 各自が、**見たまま、聞いたまま**(逐語の引用や観察した行動)を、**解釈を加えずに**、1 つの付箋に 1 つ書く。
2. 付箋を壁に貼り、**似たもの同士に分ける**(親和図)。トピック、利用者の旅の段階、画面の手順、利用者の種類で分けられる。
3. グループに名前をつけ、各グループが何を示すかを、**発見(finding)**として、短い文で書く(例:「法的な宣誓が、威圧的で分かりにくい」)。

多くの人で分析すると、**研究者の偏り**と、特定の人や関係者の影響が減る、と述べます。NN/g の記事("Why User Interviews Fail")も、**録音して、書き起こし**、チームで読んで分析するよう勧め、分析をしないと、**記憶に残った洞察だけ**が報告され、**自分の思い込みを支持する洞察**が選ばれやすい、と述べます。

### 調査の方法を選ぶ、問い(このサービスの整理)

ここからは、このサービスの整理です。

1. **知りたいことは、考えや経験か、行動か**(行動なら、観察する)。
2. **研究の問いを、チームで書いたか**(利用者に聞く質問と、学びたい問いを混ぜていないか)。
3. **質問は、開いているか、誘導していないか**(英語の目安は「did / was / is」で始まる質問。日本語では、意味で読み替えます)。
4. **誰に会ったか**(実際の利用者か。さまざまな人を含むか。自社の職員だけではないか)。
5. **解釈と観察を分けて記録し、複数人で分析したか**。
