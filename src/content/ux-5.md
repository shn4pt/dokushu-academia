### 調査は、意思決定のためにある

[UX-3](/lesson/ux-3)と[UX-4](/lesson/ux-4)で、調査と検証のやり方を学びました。しかし、調査の結果が**使われなければ**、調査は意味を持ちません。このレッスンでは、見つけたことを、**何を直すか、何を作るか、進むか止めるか**の判断につなげる方法を見ます。

NN/g の記事 "Discovery: Definition"(Rosala, 2020。2024 年に再確認と表示)は、プロジェクトの初期の**発見(discovery)**の段階を、問題の領域を調べ、解くべき問題を枠づけ、次に何をするかについて十分な証拠と方向を集める段階と説明します。そして、発見が目指すものは、**解くべき問題と、望ましい成果についての合意**だと述べます。発見の成果として、次の 3 つの理解と、もう 1 つ(共有されたビジョン)を挙げます。

- **利用者の理解**:誰で、問題にどう影響を受け、何を必要とし、望み、大切にするか。
- **問題と機会の理解**:問題がなぜ、どう起きるか、利用者と組織への影響、問題の大きさ。
- **制約の理解**:現在の業務、解決策、使える技術。
- **共有されたビジョン**:関係者と協力して、事業全体の目標と望ましい成果(「何を達成したいか」「成功とはどういう状態か」)を理解し、最も効果の大きい問題に集中できるようにする。

記事は、発見をよくやっておくことで、後で提案される解決策が、**利用者にとって望ましく、組織にとって成り立ち、技術的に実現できる**ものになるようにする、と述べます。また、**仮定だけで進める**のは危険で、実は重要でない問題を解いて、時間と費用と労力を無駄にするおそれがある、とも述べます。([心理学](/course/psychology)の講座で見た、確証バイアスや、自己報告の限界とも、つながる話です。)

### 見つけた問題に、優先順位をつける

調査で見つかる問題は、すべてを直せるとは限りません。Nielsen(1994)の記事 "Severity Ratings for Usability Problems" は、使いやすさの問題の**重大度**を、3 つの要素の組み合わせと説明します。

- **頻度**:よく起きるか、まれか。
- **影響**:起きたとき、利用者が乗り越えるのは簡単か、難しいか。
- **持続性**:一度知れば乗り越えられる問題か、利用者が繰り返し悩まされるか。

そして、さらに、**市場への影響**(客観的には簡単に乗り越えられる問題でも、製品の人気に大きく響くことがある)も見る必要がある、と述べます。優先順位づけと意思決定を容易にするため、これらを**1 つの評価**にまとめるのが一般的だ、とも述べます。評価の尺度は、次の 0〜4 です。

| 点 | 内容 |
|---|---|
| 0 | 使いやすさの問題だとは思わない |
| 1 | 見た目だけの問題。時間があれば直す |
| 2 | 軽い問題。直すのは低い優先度 |
| 3 | 大きな問題。直すことが重要で、高い優先度 |
| 4 | 使いやすさの大惨事。製品を出す前に、直すことが必須 |

記事は、この評価の使い道として、**最も深刻な問題に最も多くの資源を割り当てる**ことと、使いやすさの取り組みがさらに要るかの**大まかな目安**を挙げます。大惨事級の問題が残っていれば、おそらく、公開は勧められません。逆に、見た目だけの問題ばかりなら、問題があっても公開に進むと判断することもある、と述べます。

評価をする人の数について、記事は、自分の経験として、**1 人の評価者の重大度の評価は、信頼するには不安定すぎる**と述べます。評価する人が増えるほど、平均の質は急に上がり、**3 人の評価の平均**で、実用上は十分なことが多い、とも述べます。(これは、Nielsen の経験にもとづく記述で、確かめた研究は示されていません。記事の文脈は、ヒューリスティック評価の評価者です。)

GOV.UK のサービスマニュアルも、分析の場に、調査を見た**多くの人**を呼ぶことで、**研究者の偏りを減らし**、特定の人や関係者の影響を抑え、**次に最も重要な取り組みは何か**を、グループで決められる、と述べます([UX-3](/lesson/ux-3)で見た分析セッションの記述です)。

### 結果を、どんな形で伝えるか

Nielsen(2005)の記事 "Formal Usability Reports vs. Quick Findings" は、258 人の使いやすさの実務家に、調査結果の伝え方を尋ねた結果を示します(複数回答)。

| 伝え方 | 割合 |
|---|---|
| 方法の詳細を含む、正式な書面の報告書 | 42% |
| 「早わかり(quick findings)」の報告 | 36% |
| 主な発見をまとめたメール | 24% |
| 非公式の会議、報告会 | 27% |
| 正式なプレゼンテーションの会議 | 21% |
| 発見の表計算シート | 15% |
| バグ管理のデータベースに入力 | 14% |

(ほかに、動画やポスターなど、1〜4% の方法もあります。)

記事は、**最良の一つの方法はない**と述べ、正式な報告書と簡潔な報告が主流だとします。使い分けについては、次のように述べます。

- **簡潔な報告が向く場合:** 何度もテストして設計を反復するとき。テスト直後に、見学者の非公式なメモをもとに短い報告会を開き、チーム全員に**短いメール**を送る。メールは短いほど読まれやすい。記事は、スライドの正式な発表は、速度を落とし、箇条書きでは利用者の行動の機微を捉えられず、数か月後には解釈がほぼできなくなる、と筆者の見解として述べる。
- **正式な報告書が向く場合:** **ベンチマーク調査や定量的なテスト**(測定方法を詳しく書かないと、数字を判断できず、後で再測定して比べられない)、**競合調査**、**現場調査**、**外部のコンサルタントの調査**。長く使える記録が要る場合である。

記事は、最良の報告は、**チームの共有理解を作る学習の道具**だと述べます。毎日の報告を簡潔にして、年に数本の正式な報告書に力を入れるやり方を勧めます。(この記事は、書き手の経験と、実務家 258 人の回答にもとづきます。回答者の選び方などは、記事に書かれていません。)

### チームを調査に巻き込む

意思決定に使われる調査にするには、**チームが調査を見ている**ことが大きいと、GOV.UK のマニュアルは述べます。調査の研究者はチームに組み込まれ、チームの全員が**実際の利用者を観察する**のが最も効果的で、目安として、**6 週間に少なくとも 2 時間**を挙げます。これにより、チームは、利用者の体験の浮き沈みを理解し、利用者の言葉を学び、利用者を**実在の人**として話せるようになる、と述べます。研究者が、通常、チームと**週に少なくとも 3 日**働き、**少なくとも 2 週間ごと**に調査を行うことも、目安として挙げます。

NN/g の記事 "Why User Interviews Fail"(Rosala, 2019)も、関係者が、研究の目的と、方法を選ぶ理由を理解し、**最初から巻き込まれている**とき、調査は成功する、と述べます。反対しそうな関係者を、調査の枠づけに招くことを勧めます。([UX-3](/lesson/ux-3)で見たとおりです。)

### 数字で、確かめ続ける

調査で見つけた問題の解決が、**効いたか**は、数字で確かめます。GOV.UK のサービスマニュアルは、サービスの成績を測る**4 つの重要業績指標(KPI)**を挙げます。

- **取引あたりの費用**:利用者がサービスの作業を完了するたびに、政府にかかる費用。
- **利用者の満足度**:サービスの体験に満足した利用者の割合。
- **完了率**:利用者が取引を成功裏に完了した割合。
- **デジタルの利用率**:非デジタルの経路でなく、デジタルのサービスを選んだ利用者の割合。

マニュアルは、**測定値**(2000 人が試み、1000 人が完了した)を組み合わせて**指標**(完了率 50%)にする例を挙げます。そして、**発見と初期の段階から**、分析担当者をチームに入れるか、頼れるようにし、指標を決めはじめるよう述べます(このほかに、サービスごとに選ぶ KPI もあります)。得た数字の使い方として、たとえば、**完了率**から、利用者が離脱する段階を見つけたら、**研究者と調査を計画して、なぜかを理解する**よう述べます。また、年齢などの特徴で利用者を分けて、あるグループが完了しにくいと分かれば、そのグループを対象にした調査を計画できる、とも述べます。(数字が問題の場所を示し、調査が理由を示す、という使い分けです。次のレッスンで、くわしく見ます。)

### 結果を意思決定につなげる、問い(このサービスの整理)

ここからは、このサービスの整理です。

1. **見つけたことは、問題か、解決策か。** 優先順位をつける前に、問題の形にそろえているか([UX-2](/lesson/ux-2))。
2. **重大度の判断を、1 人でしていないか。** 頻度・影響・持続性・事業への影響で、複数人で評価したか。
3. **伝え方は、反復の速さに合っているか。** 簡潔な報告で回す調査と、長く残す正式な報告を、分けているか。
4. **決定する人は、調査を見たか。** 報告を読むだけでなく、利用者を見る機会があるか。
5. **直したあとに、数字で効果を確かめるか。** 数字が示す場所について、理由を調べる計画があるか。
