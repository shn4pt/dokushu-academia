# 出典の再確認

## 手順
1. 対象を決める。`npm run freshness`(確認日の古さ)と `npm run freshness:links`(リンク)を実行するか、鮮度の点検の issue を読む。`npm run sources:report` は、確認日の古い順の作業リスト。
2. 対象のレッスンごとに、出典の記録(`src/data/lesson-sources.json`)の URL を、**実際に取得して読み直す**。
   - 内容が変わっていれば(改正、版の更新、価格の変更)、本文を直し、記録の `changes` に、日付と要約を足す。
   - 変わっていなければ、本文はそのままにする。
   - 取得できない(遮断・リンク切れ)なら、別の経路を探す。探せなければ、そのレッスンの確認日は更新せず、記録の `note` に「いつ、何が取得できなかったか」を書く。
3. **実際に読み直した出典だけ**を根拠に、`checkedAt` を、その日の日付に更新する。一部しか読み直していないなら、`status` を `partial` に下げるか、`note` に範囲を書く。
4. 法令・基準の講座は、条文と施行日・改正の有無を、必ず確認する。確認日は 90 日以内に保つ(超えるとテストが失敗し、公開できない)。
5. 検査(`npm run build`、`npx playwright test`)を通す。コミットしてから `npm run history`。push は、本人の承認のあと。

## 禁止
- 読み直していないのに、確認日だけを更新しない。
